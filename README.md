# Q-Vela

Q-Vela is a QEMU-based RISC-V virtual emulation platform for validating system software features defined in the [Vela](https://github.com/riscv-vela/vela) project. It extends upstream QEMU with emulation support for three key subsystems:

- **[VelaNPU](qemu/hw/misc/gemmini/README.md)** — Systolic array-based NPU (matrix-matrix multiplication accelerator) with ternary GEMM support
- **[Custom Vector ISA](docs/isa.md)** — Custom vector instructions for RoPE, tokenizer acceleration, and PID control
- **[TEE](docs/tee.md)** — Trusted Execution Environment via WorldGuard memory protection and Keystone enclave framework
- **[RAS](docs/ras.md)** — Reliability, Availability, and Serviceability via RISC-V Error Record Interface (RERI)

The platform is used for function-level testing of RISC-V system software before validation on the FPGA-based hardware platform (i.e., [i-vela](https://github.com/riscv-vela/i-vela), [f-vela](https://github.com/riscv-vela/f-vela)). In addition, _VelaNPU_ and _Custom Vector ISA_ replicate the functional behavior of the [f-vela](https://github.com/riscv-vela/f-vela)'s NPU/VPU within the QEMU environment, providing equivalent emulation.

## Repository Structure

```
q-vela/
├── qemu/                      # Modified QEMU source (VelaNPU + RERI + WorldGuard)
│
├── patch/                     # Patches for firmware and kernel components
│   ├── opensbi_reri.patch     # OpenSBI: RERI support
│   ├── opensbi_tee.patch      # OpenSBI: TEE/WorldGuard support
│   ├── edk2_reri.patch        # EDK2 UEFI: RERI support
│   ├── kernel_reri.patch      # Linux kernel: RERI support
│   └── *.sh                   # Patch application scripts
│
├── buildroot/                 # Submodule — lightweight root filesystem builder
├── edk2/                      # Submodule — UEFI firmware
├── linux/                     # Submodule — Linux kernel
├── opensbi/                   # Submodule — RISC-V SBI firmware (M-mode bootloader)
│
├── reri register generator/   # RERI register specification tool (Excel-based)
│
└── docs/                      # Per-subsystem documentation
    ├── isa.md
    ├── tee.md
    └── ras.md
```

## Getting Started

### Prerequisites

The following packages are required to build and run QEMU (Ubuntu/Debian):

```bash
# Build dependencies
sudo apt install git build-essential ninja-build pkg-config \
    libglib2.0-dev libpixman-1-dev python3 python3-venv flex bison

# Cross compiler (for firmware) & guest bootloader
sudo apt install gcc-riscv64-linux-gnu u-boot-qemu

# Rust toolchain (for the Security Monitor linked into OpenSBI)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Guest image creation dependencies (used by vela's init.sh)
sudo apt install debootstrap parted qemu-utils
```

### Clone

```bash
git clone https://github.com/riscv-vela/q-vela.git
cd q-vela
```

> Submodules (`buildroot/`, `edk2/`, `linux/`, `opensbi/`) are **not** required
> to build QEMU itself. Initialize them only when building firmware or kernel
> components: `git submodule update --init <name>`

### Build QEMU

```bash
cd qemu
./configure --target-list=riscv64-softmmu
make -j$(nproc)
cd ..
```

### Build Output

After a successful build, the following files are generated under `qemu/build/`:

| File | Description |
|------|-------------|
| `qemu/build/qemu-system-riscv64` | RISC-V 64-bit system emulator with VelaNPU, Custom Vector ISA, RERI, and WorldGuard support |
| `qemu/build/qemu-img` | Disk image creation/conversion utility |

Verify the build:

```bash
./qemu/build/qemu-system-riscv64 --version                # prints the QEMU version
./qemu/build/qemu-system-riscv64 -device help | grep gemmini   # confirms the VelaNPU device is available
```

### Build Firmware (vela-fws)

The firmware components (OpenSBI, EDK2) are maintained in the separate
**[vela-fws](https://github.com/riscv-vela/vela-fws) repository**.

### Build Kernel (vela-linux)

The Linux kernel and the Keystone kernel driver are maintained in the separate
**[vela-linux](https://github.com/riscv-vela/vela-linux) repository**.

### Prepare a Guest Image

The guest root filesystem image is generated by the **[vela](https://github.com/riscv-vela/vela)
repository** — the base project that defines the Vela system software stack.
Clone it and run `init.sh`, which builds an Ubuntu 24.04 (noble) RISC-V image
via debootstrap:

```bash
git clone https://github.com/riscv-vela/vela.git
cd vela
./init.sh        # requires sudo; creates the image in the current directory
cd ..
```

This produces **`vela/ubuntu-noble-riscv64.img`** (16 GiB raw image) with:
- a default user `vela` (empty password, sudo-enabled)
- SSH server enabled

### Launch

Save the following as `run.sh` in the repository root and execute it:

```bash
#!/bin/bash
./qemu/build/qemu-system-riscv64 \
    -machine virt,wg=on -nographic -m 16384 -smp 4 \
    -bios ./vela-fws/opensbi/build/platform/generic/firmware/fw_jump.bin \
    -kernel ./vela-linux/linux/arch/riscv/boot/Image \
    -append "root=/dev/vda1 rw console=ttyS0 earlycon=sbi" \
    -cpu rv64,v=true,vlen=512,vext_spec=v1.0,zba=true,zbb=true,zbs=true,zbc=true,zbkb=true,zcb=true,zicond=true \
    -accel tcg,thread=multi \
    -semihosting-config enable=on,target=native,userspace=on \
    -netdev user,id=eth0,hostfwd=tcp::2222-:22 -device virtio-net-pci,netdev=eth0 \
    -device virtio-rng-pci \
    -drive file=./vela/ubuntu-noble-riscv64.img,format=raw,if=virtio \
    -device gemmini,id=gemmini0 \
    -device gemmini,id=gemmini1 \
    -device gemmini,id=gemmini2 \
    -device gemmini,id=gemmini3 \
    -D qemu.log
```

- `-device gemmini,id=gemmini{N}` attaches N VelaNPU instances; adjust the count as needed (IDs must be `gemmini0`, `gemmini1`, ...).
- `-accel tcg,thread=multi` is recommended when attaching multiple VelaNPU devices, so that each device runs on its own worker thread.
- Once the guest has booted, log in as `vela` (no password), or connect via SSH: `ssh -p 2222 vela@localhost`
- Execution logs (VelaNPU command traces, thread IDs) are written to `qemu.log`.
